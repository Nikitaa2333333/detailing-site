# Машины и классы

Как сайт находит машину посетителя и решает, по какому классу считать цену. Коротко —
в [CLAUDE.md](../CLAUDE.md), история решений — в [journal.md](journal.md).

## Порядок доверия

Класс модели берётся из первого источника, где она есть:

1. **Таблица заказчика** — [car-overrides.json](../akb-bu/src/data/car-overrides.json)
   (из его `Классы_машин.xlsx`). С 08.10.2026 в ней класс всех ~3900 моделей, которые
   находит сайт, включая модели прайса. Главнее прайса: это его же решение, только свежее.
2. **Прайс** — лист «Классификация машин» в xlsx прайса → `prices.json`. Работает только для
   моделей, которых нет в таблице. Лист устарел: 42 модели заказчик перевёл в таблице.
3. **`car-extra.json`** — наши аналоги для машин вне прайса: класс у похожей модели прайса (`like`).
4. **Правило по размеру** (`sizeClass`) — для моделей мировой базы с габаритами.
5. **Правило по сегменту** (`segmentClass`) — если габаритов нет (база без платного ключа).

Цены на сайт не вписываются: цена услуги — столбец прайса по классу. Сменился класс —
сменилась цена.

## Таблица заказчика

**Файл:** `Классы_машин.xlsx` на Google Диске chendev.nik@gmail.com
(id `12160-Q7qJl6p5pon_bHH7HChw6f1zXLn`). Листы:

| Лист | Что там |
|---|---|
| 1. Расходится с прайсом | модели прайса, где по размеру выходит другой класс |
| 2. Премиум | дорогие марки: класс или «отдельно» |
| 3. Ходовые вне прайса | `car-extra` + свежие модели популярных марок (с 2015, выпускаются) |
| 4. У границы класса | объём в ±0,3 м³ от границы класса |
| 5. Остальные | редкие и старые модели |
| Новое (Никита) | спортверсии и другой кузов, расклеенные 09.10.2026 (SQ5, X3 M, Maybach S…) |
| ДОБАВИТЬ | правки заказчика его словами — см. ниже |

**Единственный источник классов — эта таблица на Диске.** С 09.10.2026 класс каждой машины
на сайте из неё (`npm run cars-classes`: «Без класса из таблицы заказчика: 0»). Лист
«Классификация машин» в прайсе, `like` в car-extra и правило по размеру остались только
запасом для моделей, которых в таблице ещё нет. Перед импортом — всегда свежая копия с Диска
(`uc?export=download&id=…`) в `Классы_машин_заказчик.xlsx`; других копий таблицы в корне нет.

Колонка «Ваш класс» — список «1–5 / отдельно», рядом «Комментарий». Каждая модель — на
одном листе.

**Импорт** (из `akb-bu/`):

```bash
python scripts/import-class-overrides.py "../Классы_машин_заказчик.xlsx"
npm run build
```

- Пишет класс каждой строки; `was` — что было на сайте до таблицы.
- Формулы «=G130» в «Ваш класс» (заказчик протянул «как на сайте») разворачиваются в значение.
- Комментарий «подходит» не сохраняется, остальные — в `note`.
- **Лист «ДОБАВИТЬ»** (заказчик завёл 09.10.2026): «Марка | Модель | Класс | Комментарии» его
  словами — «Ауди А3 c 2020 по н.в.», «BMW М8». Ложится поверх основных листов. Какая это
  модель на сайте — словарь `ADD_NAMES` в импортёре; новая строка, которой там нет, —
  импорт падает и называет её. Модели, которых на сайте не было, сначала заводятся в
  `car-extra.json` (с `top: true`), потом строка в `ADD_NAMES`.
- **Склейка только для одной машины.** Написание модели сайта не должно забирать другую
  модель мировой базы: спортверсия, другой кузов или размер (M5, SQ5, X3 M, Golf R, Octavia
  RS, WRX, Pajero Sport, EQE SUV, Maybach S/GLS) — своя модель со своим классом. Одна машина
  под разными именами (Honda Fit = Jazz, Infiniti FX = QX70) — список `sameCar` в
  `car-base-rules.json`. Автотест падает на склейке, которой нет в списке. До 09.10.2026
  «m5» было написанием «5 серии», и M5 считался по её классу.
- По листу 09.10.2026: BMW M2–M8, X5 M, X6 M — отдельные модели (раньше «m5», «x5m» вели на
  серию); А3 разделена: «A3 (до 2020 г.)» — модель прайса под новым именем (`car-aliases`),
  «A3 (с 2020 г.)» — `car-extra`, кузов 8Y; Maybach SL — «отдельно».
- Модель пропала из справочника (переименовали в базе) — сборка падает и называет строку.

**Новые модели.** После `npm run cars-base` в базе появляются машины, которых нет в таблице:
им класс ставит правило. `npm run cars-classes` печатает «Без класса из таблицы
заказчика: N». Набралось — собрать заказчику таблицу из этих моделей и импортировать.
Генератор таблицы 06.10 был разовым скриптом: для новой таблицы — выгрузить новые модели
(`carIndex`, у модели нет `client`) с размерами и классом в xlsx того же вида.

**Решения 08.10.2026:** заполнены все 3906 строк, изменено 314, «отдельно» — 209.
Из 42 правок своих моделей прайса 35 — ровно класс по размеру.

## «Отдельно» — премиум

Класс `p`, подпись «цена после осмотра» (`PREMIUM`, `classText` в
[lib/car-combo.js](../akb-bu/src/lib/car-combo.js)). Сейчас: все марки `brandMinClass`
(Aston Martin, Bentley, Ferrari, Lamborghini, Maserati, Maybach, McLaren, Rolls-Royce…),
AC, Audi Nuvolari и др.

- Поле машины: в подсказках и на плашке «цена после осмотра» вместо «N-й класс».
- Калькулятор: у услуг «после осмотра», итог без суммы, строка «стоимость считаем
  индивидуально — назовём после осмотра»; в заявку уходит `premium: 'цена после осмотра'`.
- Виджет класса на страницах услуг: «цена после осмотра», столбец прайса не подсвечивается.

## Мировая база (cars-base.ru)

Каталог auto.ru: ~425 марок, ~4950 моделей, ~10 100 поколений. Импорт — `npm run cars-base`
([scripts/import-cars-base.mjs](../akb-bu/scripts/import-cars-base.mjs)) → `cars-base.json`.

- **Марки и модели** — бесплатный `https://api.cars-base.ru/full`. Он склеивает модель с
  поколением («X5, III (F15)») — импортёр режет по «, ».
- **Поколения, кузов, габариты** — платный тариф «Стандарт». Ключ `CARS_BASE_TOKEN` в
  `akb-bu/.env` (в git не идёт), куплен 06.10.2026, действует до 06.01.2027, письмо от
  no-reply@cars-base.ru. Таблицы `generations`, `configurations`, `specifications`
  постранично по 1000 строк, ~130 запросов, ~1,5 минуты (лимит API — 120 в минуту на ключ,
  импортёр ждёт 0,6 с между запросами и уважает `Retry-After`).
- Модификация → конфигурация: `id` модификации до первого «_» — это `id` конфигурации.
  Габариты поколения — медиана по модификациям основного кузова.
- `-- --demo` — демо-ключ: поколения только у первых 50 марок (до BMW).
- **Копия базы** — `cars-base-backup/` в корне (CSV-таблицы `csv_exports.zip` и
  `catalog_full.xlsx`), в git не идёт.
- **Договор** (cars-base.ru/public-offer): данные можно использовать на своём сайте;
  нельзя публиковать полный архив и передавать выгрузки или ключ. В браузер уходят только
  названия и наш класс; габариты и поколения остаются на сборке. Возврата после начала
  пользования нет. Пользоваться скачанным после окончания срока — в договоре не сказано.
- Российские марки не импортируются (`skipCountries`), Lada/ВАЗ из прайса скрыты
  (`hidePriceBrands`). Модели, снятые до 1995 (`minYear`), в поиск не попадают.
- Фургонов (Sprinter, Crafter, Jumper) в базе нет — раздел «Лёгкие коммерческие» auto.ru;
  они живут в прайсе и `car-extra.json` (`noBasePair`).

## Правило по размеру

[car-base-rules.json](../akb-bu/src/data/car-base-rules.json) → `sizeClass`, код —
`sizeOf` / `sizeClass` в [lib/cars.js](../akb-bu/src/lib/cars.js).

- Объём Д×Ш×В (м³) среднего по объёму поколения из выпущенных с 2010 года (машины растут:
  5 серии G60 больше F10), нет таких — новейшее.
- Вид кузова по началу названия кузова в базе: внедорожник, пикап, минивэн, компактвэн,
  остальное — легковой. Кроссовер в каталоге auto.ru — тоже «Внедорожник».

| Вид | 1-й | 2-й | 3-й | 4-й | 5-й |
|---|---|---|---|---|---|
| Легковой | до 12,2 | до 14,3 | — | больше | — |
| Внедорожник | — | — | до 15 | до 18,4 | больше |
| Пикап | — | — | — | — | всегда |
| Компактвэн | — | до 15,9 | больше | — | — |
| Минивэн | — | — | до 16 | до 17 | больше |

- Марки `brandMinClass` — не ниже 4-го (сейчас они «отдельно» по таблице).
- В заявку уходит `like`: «правило: внедорожник 4,7×1,9×1,7 м».
- Пороги подобраны перебором по прайсу (`npm run cars-classes -- --best`). Совпадение:
  с прайсом 82% (349 моделей), с решениями заказчика 90% (304 из 336). Сегмент A–F давал 57%.
- Не ловит: престиж и спорткары (911, CLS, Panamera, LS — по размеру 1–2-й). По цене
  тоже не поймать: цена в базе есть лишь у 9% моделей вне прайса.
- **Сегмент** (без габаритов): A, B, C → 1; D, E, S → 2; M → 3; F, J → 4. Слабо: внедорожник
  от седана не отличает (BMW X5 в базе — «E»).

## Поиск машин

- Слои: прайс + `car-aliases.json` (написания, кузовные коды BMW/Mercedes) → `car-extra.json`
  → `cars-base.json` + `car-base-aliases.json` (~230 ходовых моделей базы) →
  `car-codes.json` (коды поколений: J200, Y62, MK7; от трёх знаков ищутся сами,
  двухбуквенные — только рядом с моделью).
- **Кириллица в кодах — в два захода** ([lib/car-search.js](../akb-bu/src/lib/car-search.js)).
  Первый, как всегда: слово с цифрой или из одной-двух букв читается «на вид» («х5» = X5,
  «е200» = E200, «в» = V и W). Если модель не нашлась ни точно, ни по началу названия —
  второй заход: ещё короткие слова («тсх», «брз», «атс») и прочтения «по звуку»: с = S,
  к = Q, х = H, н = N, дж/ж = J («ауди с4» — S4, «инфинити кх80» — QX80, «хаммер н2» — H2).
  Звуковое прочтение ниже «на вид» при равном совпадении: «к5» — Kia K5, а не Audi Q5.
  Два захода — ради скорости: прочтение = проход по ~4000 моделям на каждую клавишу;
  обычные запросы работают с прежней скоростью, второй заход (~40 мс) — только на кодах.
- **Подсказка, если модель не нашлась** (`similarModels`): марку узнали, модель нет —
  строка «Не нашли „с65“ — выберите из моделей Volvo», ниже до 6 похожих моделей марки
  (по расстоянию правки и первой букве), дальше вся марка. Внутри выбранной марки — то же
  плюс «искать среди всех марок». Человек не остаётся с пустым списком.
- Модели базы в выдаче ниже прайса и `car-extra`; для базы нет совпадения с серединой слова,
  опечатки — только в запросах от шести букв (иначе «лада» находит Honda Ballade).
- Рыночные версии склеены с основной моделью («Passat (North America)»), несуществующие
  модели прайса скрыты `hideModels`. Модель прайса без пары в базе и не из `noBasePair` —
  автотест падает.
- В браузер справочник уходит файлом `/cars-index.json` (`lib/car-index-pack.js`,
  ~61 КБ gzip), не в HTML.
- Автотест [scripts/test-search.mjs](../akb-bu/scripts/test-search.mjs) — 320 проверок
  «запрос → что первым», идёт перед каждой сборкой. Промах поиска — сначала строка в тест.
